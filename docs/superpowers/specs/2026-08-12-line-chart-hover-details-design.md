# 折线图悬停明细设计

## 背景

项目当前有两处原生 SVG 折线图：

- Key 查询页的每日用量弹窗，由 `internal/web/app.js` 渲染。
- 自助查询页的近 N 天用量区域，由 `internal/web/self.js` 渲染。

Key 查询页已经支持在绘图区内按横坐标吸附最近数据点并显示日期和费用，自助查询页尚未支持。此次改动统一两处折线图的悬停行为，不引入新的图表依赖，也不调整接口或数据结构。

## 交互设计

鼠标位于任一折线图绘图区内时，图表根据鼠标的 SVG 横坐标选择距离最近的数据点，不要求鼠标精确命中点位。选中点从半径 3 放大到半径 5，并切换为现有主题对应的强调色。

提示框展示该点的完整横纵坐标明细：

- 横坐标：原始日期字符串，例如 `2026-08-12`。
- 纵坐标：以美元符号开头并保留 4 位小数，例如 `$1.2345`。

提示框优先位于点位上方；上方空间不足时放到下方。其横向位置限制在绘图区左右边界内，避免内容被 SVG 裁切。鼠标离开绘图区或 SVG 后，提示框隐藏，原高亮点恢复默认半径和颜色。

## 实现方案

沿用 Key 查询页现有的原生 SVG 实现，将相同行为补到自助查询页。两份脚本保持各自当前的图表尺寸、坐标轴刻度和标题，只统一以下行为契约：

- 调色板包含提示框背景、日期文本、金额文本和悬停点颜色。
- 数据点保留可被高亮的引用。
- SVG 包含默认隐藏的提示组、背景矩形、日期文本和金额文本。
- `mousemove` 将浏览器坐标换算为 SVG 坐标，在绘图区内选择横向最近点。
- 提示逻辑更新点位高亮、文本和边界受限的位置。
- 隐藏逻辑恢复点位并隐藏提示组。
- `mouseleave` 以及移出绘图区都会触发隐藏逻辑。

本次不抽取共享 JavaScript 模块。当前静态资源是独立嵌入和加载的脚本，为两张图抽取模块会扩大资源注册、加载顺序和页面回归范围，收益不足以覆盖额外复杂度。

## 数据与错误处理

悬停明细只消费图表渲染前已经通过校验的 `date` 和 `actualCost`。金额继续使用现有数值转换方式，非有限值按 0 展示；该防御分支与折线坐标计算保持一致。

空数据仍不渲染 SVG，也不会注册悬停监听器。单点数据的吸附与提示框定位沿用现有居中坐标逻辑。

## 可访问性与主题

保留 SVG 现有的 `role="img"` 与中文 `aria-label`。悬停提示是对可视图表的增强，不替代页面已有的明细表或摘要信息。

提示框颜色分别适配亮色和暗色主题，使用现有图表色彩体系。提示组不接收指针事件，避免其显示后干扰鼠标移动判定。

## 测试与验收

按 TDD 增加静态资源回归测试，先验证自助查询脚本缺失统一悬停契约，再补最小实现。测试应确保两份折线图脚本都包含：

- 提示框元素和日期、金额文本更新。
- 最近点选择逻辑。
- 绘图区边界判断。
- 显示、隐藏和点位恢复行为。
- 鼠标移动与离开事件监听。

完成后运行相关 Go 单元测试、完整 Go 测试和构建。浏览器验收覆盖亮色/暗色与桌面/窄视口，实际触发两张图的悬停，确认日期和 4 位小数金额可见、点位高亮、提示框不越界，移出后隐藏。

## 非目标

- 不改变后端 API、每日用量数据结构或日期范围选择。
- 不引入第三方图表库。
- 不增加点击锁定、触摸手势或键盘数据点导航。
- 不重构其他页面或图表样式。
